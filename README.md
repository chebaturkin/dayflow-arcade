# линия дня

«линия дня» показывает один календарный день как горизонтальную трассу. события становятся станциями, свободное время — открытыми участками, а текущий момент — красной линией.

это статический офлайн-инструмент. календарь разбирается в браузере, данные остаются в браузере, а внешний сервер не нужен.

## что здесь можно сделать

- выбрать дату и часовой пояс;
- загрузить ICS-файл перетаскиванием или через диалог выбора;
- начать с примера, добавить событие вручную, изменить или удалить его;
- отмечать выполненные события и отменять последнее действие;
- видеть all-day события, свободные окна, повторения `DAILY` и `WEEKLY`, пересечения и события на границе дня;
- скачать текущую трассу в `SVG` или `PNG`;
- переключить спокойный или аркадный режим.

события, отметки выполнения, режим и часовой пояс сохраняются в `localStorage` текущего браузера. ICS и экспорт никуда не отправляются.

## запустить локально

сборка не нужна. из корня проекта запустите статический сервер:

```bash
python3 -m http.server 4173
```

откройте <http://localhost:4173>. запуск через `file://` не подходит: браузер блокирует ES-модули из локального файла.

## проверить проект

календарное ядро и контракт интерфейсного текста проверяются встроенным тестовым раннером Node:

```bash
node --test tests/calendar-core.test.mjs tests/copy-contract.test.mjs
node --check js/app.js
node --check js/calendar-core.js
```

для браузерного smoke-прохода нужен Playwright для Python. в одном терминале оставьте сервер:

```bash
python3 -m http.server 4173
```

во втором терминале запустите проверку:

```bash
python3 tests/browser_smoke.py
```

smoke-проверка проходит пустой день, пример, ручное событие, редактирование, undo, ошибочный и слишком большой импорт, восстановление после перезагрузки, клавиатурный dropzone, мобильную ширину и экспорт.

## пример ICS

сохраните текст как `sample.ics`, затем выберите его в «линии дня»:

```ics
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//Linia Dnya//EN
BEGIN:VEVENT
UID:briefing@example.test
DTSTART;TZID=Europe/Moscow:20261008T090000
DTEND;TZID=Europe/Moscow:20261008T094500
SUMMARY:утренний брифинг
LOCATION:платформа 2
DESCRIPTION:сверить маршрут и выбрать один главный рейс.
END:VEVENT
BEGIN:VEVENT
UID:focus@example.test
DTSTART;TZID=Europe/Moscow:20261006T110000
DTEND;TZID=Europe/Moscow:20261006T123000
RRULE:FREQ=WEEKLY;BYDAY=TU;COUNT=6
SUMMARY:глубокая работа
END:VEVENT
BEGIN:VEVENT
UID:holiday@example.test
DTSTART;VALUE=DATE:20261008
DTEND;VALUE=DATE:20261009
SUMMARY:день без встреч
END:VEVENT
END:VCALENDAR
```

поддерживаются UTC, `TZID`, floating-время, all-day, `DURATION`, `EXDATE` и повторения `DAILY/WEEKLY`. сложные правила сообщаются в интерфейсе и не удаляют уже сохранённый день.

## опубликовать на GitHub Pages

1. создайте репозиторий и отправьте содержимое проекта в ветку `main`;
2. откройте **Settings → Pages** и в качестве источника выберите **GitHub Actions**;
3. дождитесь workflow **publish to GitHub Pages** — он соберёт статический artifact и опубликует сайт;
4. для этого репозитория страница доступна по адресу [`chebaturkin.github.io/dayflow-arcade`](https://chebaturkin.github.io/dayflow-arcade/).

workflow лежит в `.github/workflows/pages.yml`. секреты, сборщик и backend для сайта не нужны.

## ограничения

трасса показывает один выбранный день. данные хранятся на текущем устройстве; очистка данных сайта удалит сохранённые события и настройки. календарь не подключается к внешним API и не синхронизирует изменения обратно в исходный календарь.

# «линия дня» — редактура голоса и интерфейса

## цель

Сделать из текущего офлайн-календаря цельный продукт в стиле Тимофея: спокойно объяснить, что происходит с днём, назвать каждое действие человеческим языком и сохранить рабочую механику импорта, ручных событий, выполнения, локального хранения и экспорта.

## рамки

- календарное ядро в `js/calendar-core.js` сохраняется; пересмотр возможен только там, где аудит найдёт реальную ошибку или небезопасное поведение;
- сайт остаётся статическим, без аккаунтов, серверных запросов, аналитики и календарных API;
- данные ICS читаются только в браузере и не уходят из текущей вкладки;
- название продукта — «линия дня»; `ICS`, `UTC`, `PNG`, `SVG`, URL, имена файлов и технические ключи сохраняют нормативный регистр;
- русский текст интерфейса, README, описания ошибок, empty states, метаданные и GitHub-инструкции получают строчные начала фраз, если это не собственное имя и не обязательный технический формат;
- не добавляются неподтверждённые обещания, цифры, личные истории или рекламные оценки.

## редакторский голос

Текст отвечает на вопрос читателя и сразу показывает действие. «Загрузить пример» остаётся действием, а рядом появляется короткое объяснение, зачем это нужно. Ошибка говорит, что случилось и что попробовать дальше. В интерфейсе используется «вы» только там, где обращение действительно помогает; большинство коротких подписей остаются безличными и конкретными.

Ритм спокойный, без служебных заглавных, лозунгов и искусственной геймификации. Важные слова можно выделить цветом и композицией, но не капсом. Живые формулировки вроде «день пока пуст» сохраняются, если они помогают понять состояние.

## визуальная система

Сохраняется основа табло: бумажный фон, чёрный текст, кобальтовый акцент, сигнальный красный и зелёная отметка выполнения. Обновляется иерархия:

- название и заголовки секций начинаются со строчной буквы;
- служебные бейджи вроде `ICS / EVENT` переводятся в короткие русские подписи без лишнего статуса;
- кнопки называют продолжение действия: «выбрать ICS», «загрузить пример», «сохранить событие», «скачать SVG»;
- пустой день, ошибки импорта и выбранное событие имеют равную визуальную ясность;
- dropzone получает настоящий клавиатурный фокус и роль кнопки;
- сохранены focus-visible, forced-colors, reduced motion, горизонтальная прокрутка трассы на 320px.

## текстовый охват

Редактируются все опубликованные строки и их динамические аналоги:

1. `index.html`: title, description, skip link, заголовки, подписи контролов, легенда, доступные названия, диалог и placeholders.
2. `js/app.js`: статус загрузки, уведомления, ошибки, undo, импорт, действия с событиями, детали и экспорт.
3. `js/calendar-core.js`: только пользовательские ошибки и демо-события, без изменения календарной математики.
4. `README.md`: короткое объяснение продукта, локальный запуск, приватность, пример ICS, GitHub Pages и ограничения.
5. GitHub Pages: `.github/workflows/pages.yml`, `.nojekyll`, `404.html` и ссылки/описания, необходимые для публикации из ветки `main`.

Точные названия форматов и календарных полей (`BEGIN:VEVENT`, `DTSTART`, `RRULE`) не переводятся внутри кода и примера ICS.

## надёжность и безопасность

- импорт ограничивается разумным размером файла до чтения текста, чтобы случайно выбранный огромный файл не съел память вкладки;
- dropzone принимает только `File` и проверяет расширение/тип по факту содержимого, сохраняя локальный сценарий для нестандартных MIME;
- всё пользовательское содержимое продолжает попадать в DOM через `textContent`; SVG-экспорт экранирует текст;
- восстановление localStorage проверяет настройки, список событий и completion-словарь раздельно, чтобы одна повреждённая запись не сбрасывала весь день;
- повторный импорт и удаление по-прежнему можно отменить; при полностью неверном файле старый день остаётся на месте;
- публикация использует GitHub Actions Pages artifact без секретов и без внешнего сервера приложения.

## проверка результата

- `node --test tests/calendar-core.test.mjs`;
- `node --check js/app.js` и `node --check js/calendar-core.js`;
- браузерный smoke проход на пустом дне, демо, ручном событии, редактировании, undo, ошибке импорта, перезагрузке, клавиатуре, 320px, SVG и PNG;
- ручной просмотр всех экранных строк через `rg` с проверкой капса, технических исключений и единого названия продукта;
- проверка GitHub Pages workflow YAML и локальный запуск через `python3 -m http.server`.

## критерии готовности

Готовая версия сохраняет все проходящие сейчас тесты, не добавляет сетевых запросов и не меняет смысл календарной математики. Новый пользователь понимает, что сделать на пустом экране, что случилось при ошибке импорта и как вернуть последнее действие. В исходниках и README нет случайных заглавных служебных фраз, противоречивых названий кнопок и инструкций, завязанных на личный абсолютный путь.
